# TombTweaks 1.21.1 (NeoForge) — plan implementacji

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** `mc1.21.1/` — build NeoForge 21.1 dla Tombstone 9.5.6 z funkcjami: restore, decay, cooldown ksiąg, klucze odporne na Soulbound. Wyłączanie enchantów **nie dotyczy** 1.21.1 (spec `2026-10-16-multiversion-design.md`).

**Architecture:** Niezależny build Gradle w `mc1.21.1/`, kompilujący wspólny `../core` przez `srcDir`. Kod `platform`/`feature`/`mixin` portowany z `mc1.20.1/` według tabeli zmian API poniżej. NeoForge 1.21.1 ma w runtime nazwy oficjalne → bez refmapy, bez reobfuskacji, bez procesora adnotacji Mixin.

**Tech Stack:** Gradle 8.10+, ModDevGradle 2.0.x (`net.neoforged.moddev`), NeoForge 21.1.x, Java 21 (toolchain), JUnit 5. Tombstone z CurseMaven: `curse.maven:corail-tombstone-243707:8842741` (= 9.5.6).

**Źródło prawdy dla zachowania:** pliki w `mc1.20.1/src/` + `CLAUDE.md` (niezmienniki). Port ma zachować KAŻDY niezmiennik, komentarz-uzasadnienie i nazwę klucza NBT.

- [ ] `StackViews` — **nowy klucz NBT**. `ItemKey` musi mieć hash stabilny między restartami JVM (snapshoty są zapisywane). `DataComponentPatch.hashCode()` się do tego **nie nadaje**: komponenty trzymają `Holder`-y z hashem tożsamościowym. Hashujemy więc zserializowaną postać:

```java
    public static ItemKey keyOf(ItemStack stack, HolderLookup.Provider registries) {
        return new ItemKey(idOf(stack), componentsHash(stack, registries));
    }

    /**
     * Hash komponentow stacka, stabilny miedzy restartami: liczony z NBT po serializacji,
     * bo DataComponentPatch.hashCode() zalezy od Holderow z hashem tozsamosciowym.
     * Ilosc stacka nie wchodzi do hasha (percentLossOnDeath zmienia ja w grobie).
     */
    private static int componentsHash(ItemStack stack, HolderLookup.Provider registries) {
        DataComponentPatch patch = stack.getComponentsPatch();
        if (patch.isEmpty()) {
            return 0;
        }
        return DataComponentPatch.CODEC
                .encodeStart(registries.createSerializationContext(NbtOps.INSTANCE), patch)
                .result()
                .map(Tag::hashCode)
                .orElse(0);
    }
```

  `idOf(Item)` / `idOf(ItemStack)` przez `BuiltInRegistries.ITEM`. `view(stack)`: `enchantmentIds()` z `stack.getTagEnchantments().keySet()` → `holder.unwrapKey().map(k -> k.location().toString())`; `nbtString(key)` z `stack.get(DataComponents.CUSTOM_DATA)` → `copyTag()`, `contains(key, Tag.TAG_STRING)`. Zaktualizuj komentarz configu `protectedNbtStrings`: „top-level string keys of the item's custom_data component".
