# TombTweaks 1.21.1 (NeoForge) — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** `mc1.21.1/` — a NeoForge 21.1 build for Tombstone 9.5.6 with the features: restore, decay, book cooldown, grave keys immune to Soulbound. Disabling enchantments is **not applicable** to 1.21.1 (spec `2026-10-16-multiversion-design.md`).

**Architecture:** An independent Gradle build in `mc1.21.1/`, compiling the shared `../core` via `srcDir`. The `platform`/`feature`/`mixin` code is ported from `mc1.20.1/` according to the API change table below. NeoForge 1.21.1 uses official names at runtime → no refmap, no reobfuscation, no Mixin annotation processor.

**Tech Stack:** Gradle 8.10+, ModDevGradle 2.0.x (`net.neoforged.moddev`), NeoForge 21.1.x, Java 21 (toolchain), JUnit 5. Tombstone from CurseMaven: `curse.maven:corail-tombstone-243707:8842741` (= 9.5.6).

**Source of truth for behaviour:** the files in `mc1.20.1/src/` + `CLAUDE.md` (invariants). The port must preserve EVERY invariant, every rationale comment and every NBT key name.

## API change table: Forge 47 (mc1.20.1) → NeoForge 21.1 (mc1.21.1)

| 1.20.1 | 1.21.1 |
|---|---|
| `net.minecraftforge.common.ForgeConfigSpec` | `net.neoforged.neoforge.common.ModConfigSpec` (same builder methods) |
| `ModLoadingContext.get().registerConfig(...)` | `container.registerConfig(ModConfig.Type.COMMON, SPEC, "tombtweaks-common.toml")` in the constructor `@Mod(…) TombTweaks(IEventBus modBus, ModContainer container)` |
| `@Mod.EventBusSubscriber(modid = …)` | `@EventBusSubscriber(modid = …)` (`net.neoforged.fml.common.EventBusSubscriber`), GAME bus by default |
| `net.minecraftforge.eventbus.api.SubscribeEvent` / `EventPriority` | `net.neoforged.bus.api.SubscribeEvent` / `EventPriority` |
| `net.minecraftforge.event.entity.living.LivingDeathEvent` | `net.neoforged.neoforge.event.entity.living.LivingDeathEvent` |
| `net.minecraftforge.items.IItemHandler` | `net.neoforged.neoforge.items.IItemHandler` |
| `ForgeRegistries.ITEMS.getKey(item)` | `BuiltInRegistries.ITEM.getKey(item)` |
| `Player.PERSISTED_NBT_TAG` | **still exists** in NeoForge 21.1.262 (`"PlayerPersisted"`; corrected after Task 2 — the plan originally assumed it was gone). The implementation uses an equal-valued local constant. `ServerPlayer.restoreFrom` copies it unconditionally (Task 1 bytecode) |
| `stack.getTag()` + `CompoundTag.hashCode()` in `ItemKey` | **new**: the hash of the serialized `DataComponentPatch` — see Task 2 |
| `EnchantmentHelper.getEnchantments(stack)` → `Map<Enchantment,Integer>` | **`EnchantmentHelper.getEnchantmentsForCrafting(stack)`** → `ItemEnchantments`; id via `holder.unwrapKey()`. Corrected after Task 2: the originally planned `stack.getTagEnchantments()` reads only `ENCHANTMENTS`, so an enchanted book (`STORED_ENCHANTMENTS`) would silently lose decay protection; `getEnchantmentsForCrafting` makes the same book/non-book split as 1.20.1 |
| `StackView.nbtString(key)` reads the stack's tag | reads `DataComponents.CUSTOM_DATA` (`CustomData.copyTag()`); no component → `null` |
| `ovh.corail.tombstone.api.capability.ISoulConsumer` | `ovh.corail.tombstone.api.item.ISoulConsumer` |
| `BlockWritableGrave` | `BlockEntityWritableGrave` |
| `Helper.isSoulbound(ItemStack)` | `Helper.isSoulbound(ItemStack, Level)` |
| `BlockDecorativeGrave.use` (+ refmap `m_6227_`) | `BlockDecorativeGrave.useItemOn` (official name, no refmap) |
| `mods.toml` + manifest `MixinConfigs` | `META-INF/neoforge.mods.toml` with `[[mixins]] config="mixins.tombtweaks.json"` (NeoForge reads this field) |
| `MixinTombstoneEnchantment` | **not ported** — in 1.21 the enchantments are JSON |
| `GraveKeyPolicy.refusesEnchantment` | **not ported** — the anvil will not put Soulbound on the key anyway |

Unchanged: `Inventory.items/armor/offhand` (public in 1.21.1), `Containers.dropItemStack`, `level.random`, `GameRules.RULE_KEEPINVENTORY`, `Component.translatable`, `displayClientMessage`, `CompoundTag`/`ListTag` (`getList(key, type)`, `getCompound`, `getLong` etc. — as in 1.20.1).

- [ ] `StackViews` — **a new NBT key**. `ItemKey` must have a hash that is stable across JVM restarts (snapshots are saved). `DataComponentPatch.hashCode()` is **not suitable** for this: the components hold `Holder`s with an identity hash. So we hash the serialized form:

```java
    public static ItemKey keyOf(ItemStack stack, HolderLookup.Provider registries) {
        return new ItemKey(idOf(stack), componentsHash(stack, registries));
    }

    /**
     * Hash of the stack's components, stable across restarts: computed from the NBT after
     * serialization, because DataComponentPatch.hashCode() depends on Holders with an identity hash.
     * The stack count is not part of the hash (percentLossOnDeath changes it in the grave).
     */
    private static int componentsHash(ItemStack stack, HolderLookup.Provider registries) {
        DataComponentPatch patch = stack.getComponentsPatch();
        if (patch.isEmpty()) {
            return 0;
        }
        return DataComponentPatch.CODEC
                .encodeStart(registries.createSerializationContext(NbtOps.INSTANCE), patch)
                .result()
                .map(Tag::hashCode)
                .orElse(0);
    }
```

  `idOf(Item)` / `idOf(ItemStack)` via `BuiltInRegistries.ITEM`. `view(stack)`: `enchantmentIds()` from `EnchantmentHelper.getEnchantmentsForCrafting(stack).keySet()` (not `getTagEnchantments()` — see the API table) → `holder.unwrapKey().map(k -> k.location().toString())`; `nbtString(key)` from `stack.get(DataComponents.CUSTOM_DATA)` → `copyTag()`, `contains(key, Tag.TAG_STRING)`. Update the comment of the `protectedNbtStrings` config: "top-level string keys of the item's custom_data component".
